Where the 4 GB went

A harness is the program that wraps a language model and lets it act: it holds the conversation, gives the model tools, and runs them when asked. Claude Code and Codex CLI are harnesses. Everything below follows from what a harness has to write down in order to survive a crash, resume a session, and undo a bad edit.

The five ways this bites you

The one that matters most

.gitignore does not protect you. It stops a file being committed. It does nothing to stop the agent reading that file and writing its contents into the transcript. If the agent runs grep -rn "API_KEY" . once, your keys are in plain text in your home directory, for 30 days on Claude Code and forever on Codex.

Nothing in that chain is a bug. Each step does its job. The composition is what fails.

The attack is real, not theoretical

A project's .claude/settings.json can define a hook: a shell command the harness runs by itself when a session starts. So a file committed to a repository can cause code to run on your machine the moment you point an agent at it. You never typed anything.

The ChainDrop worm did exactly this across more than 400 compromised npm packages, planting a SessionStart hook that ran node .claude/setup.mjs. It hunted for credentials from Anthropic, Codex, Cursor, OpenAI, and Gemini, alongside AWS, GCP, Azure, GitHub, Vault, SSH, and Kubernetes.

# thirty seconds, before opening any repo you did not write
ls -la .claude/ .codex/ .vscode/ 2>/dev/null
grep -rn '"hooks"\|"command"\|SessionStart' .claude/ .codex/ 2>/dev/null

find ~/.claude/session-env -mindepth 1 -maxdepth 1 -type d -empty -delete
Handle worktrees by hand

839 MB sat in a single orphaned git worktree. A worktree is a second checkout of one repository. Background agents get their own so they do not disturb your files. This one's parent repository had been moved, so both ends of the git link were broken and git worktree prune could not see it.

Check each one, then delete. They can hold work that exists nowhere else.

for w in ~/.codex/worktrees/*/*; do
  printf '%s  ' "$(du -sh "$w" | cut -f1)"
  git -C "$w" status --porcelain >/dev/null 2>&1 \
    && echo "LIVE   $w" || echo "ORPHAN $w"
done

What the harness knows about you

MEASURED, from a single 95.5 KB file at ~/.claude.json:

  • 43 projects tracked, each with its own cost, token counts, and timing history
  • 487 cached feature flags, which are remote switches that change behaviour without an update
  • a stable 64-character machine identifier
  • your account email, organisation name, role, and billing tier
  • for each project, a sample of filenames read from your repository

And from ~/.codex/config.toml: every directory you have ever marked as trusted, listed by full absolute path, kept permanently. For a consultant, that is a client list. For anyone under a non-disclosure agreement, it is a list of things you were not supposed to name.

Neither list is pruned when a project ends or when the directory stops existing. Both tools on the sampled machine still listed a repository that had been moved months earlier.

What is not a problem

Said plainly, so the rest of the list stays credible.

  • Shell snapshots are not an environment dump. MEASURED: one 4,501-line snapshot held 127 shell functions, 4 aliases, and exactly one export, for PATH. It captures shell definitions, not your environment variables.
  • File permissions are correctly applied. Both tools set 0600 on sensitive files. That part is done right.
  • Nothing observed was undisclosed data collection. Every file examined had an obvious engineering purpose: crash recovery, resume, undo, correct command execution.
The one-line version

These tools are not doing anything sneaky. They are doing ordinary engineering things, which happen to include writing your entire working life to plain text in a folder you never open. The problem is not that the files exist. It is that they outlive the task that created them, hold more than the task needed, and no part of the interface ever mentions them.

Limits of this research

Read these before quoting any number.

  • One machine, one operating system, one point in time. Every measurement is a single sample. It proves a file class exists. It does not establish a typical size. Your ~/.codex will not be 3.68 GB.
  • macOS only. Credential storage differs on Linux, which changes the risk picture materially.
  • Heavy usage skews the absolutes upward. The proportions transfer better than the raw sizes.
  • No network capture was done. Claims about what is transmitted come from documentation and locally queued telemetry, not from watching traffic.
  • Undocumented is a claim about documentation coverage, not intent.
